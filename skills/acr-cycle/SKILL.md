# 无状态执行

**定位**：工具层，无状态。上下文全来自 PROGRESS.md，cycle 不存任何内部状态。

**前置**：progress 已接收 plan 产出的初始态 + 计划侧对账已过。cycle 入口 = progress 把初始态交给 cycle。

## 执行：子需求循环 + 游标

一次一个子需求，按依赖序（progress 里锁好的拓扑序）逐个执行。

```
对每个 Mx.y（progress 里的依赖序）：
  读 progress 里的游标位置 → 从 ⏳ 那步续做

  ① 定标准    从 spec 拿验收标准；不可判 → 打回 spec 重写
  ② 定接口    从 spec 详细设计拿接口 / 边界 / 错误处理
  ③ 失败测试  **写测试 → 真跑确认红 → 贴红输出到 PROGRESS.md**（硬约束，见下）
  ④ 最小实现  只做到让刚才那个测试绿 —— 不许多写一行投机代码
  ⑤ 全量验证  不是只跑本子需求 —— 跑所有测试 + 手工验证边界
  ⑥ 自检+证据 命令 + 原始输出（必须在本轮对话内）
  ⑦ 收点 ✅   立刻写 PROGRESS.md
              → 触发 F1：没有本轮新鲜证据不许写 ✅
```

**四条规矩**：**一次一个子需求**；**不攒到最后一起验证**；**每点完成必带证据**；**收点是原子的**。

### 第 ③ 步：RED 必须真看到失败（硬约束）

不是"应该写失败测试"，是**必须看到失败才能继续**。流程：

1. **写测试** —— 按 spec 验收标准写一条最小测试（垂直切片，一次一个 seam）
2. **执行测试** —— 必须真跑一遍（`pytest -v tests/test_x.py::test_y` 或等价命令）
3. **确认红** —— 测试输出必须显示 FAIL / ERROR / assertion failed，**不是 passing**
4. **记录** —— 把**红的输出片段**（`FAILED tests/test_x.py::test_y - AssertionError...`）贴进 PROGRESS.md 本子需求的内部步骤游标

**违反即停**：如果测试一上来就是绿的（因为前一个子需求顺带实现了），不能静默跳过。必须：
1. **显式声明** —— 说清为什么前一个子需求让它绿了
2. **反向验证** —— 现场把实现改坏（注释掉 / 改个值），确认测试真的会红，再改回来
3. **贴红输出** —— 反向验证时的红输出也要贴进 PROGRESS.md

**为什么**：Superpowers 指出 AI 写测试的最大问题是"**假装失败**"——AI 写完测试直接写实现，跳过真的执行，所以测试可能永远不会失败（或者永远不会真过）。真跑红 = 锁住测试真的能测到东西。

### 收点 = F1 事实对账

progress 里写 ✅ 的**那一刻**，F1 触发。cycle 收点的完整 checklist 见 [acr-progress/reference/quality-checklist.md](../acr-progress/reference/quality-checklist.md) §5：
- 验收命令的**原始输出必须在本轮对话内**
- 三天前跑的不算、引用不算、摘要不算
- 没证据 → 不许写 ✅，重跑验证

**cycle 自己不做 F2/F3**——那是 progress 收尾时的事。cycle 只做 F1（收点即触发）。

## cycle 写 PROGRESS.md 什么

cycle 执行中**只读 progress 初始态，只写 progress 状态**：

| 写什么 | 时机 |
|---|---|
| 内部步骤游标（⏳→✅ 等） | 每完成一步 |
| 子需求状态 ✅⏳⬜ | 收点时 |
| 证据（命令 + 原始输出） | 收点时 |
| 需求回写（发现偏差时） | 随时 |
| 阻塞说明 | 遇到阻塞时 |

cycle **不直接改 prd.md / spec.md**——发现偏差时写 progress 的需求回写栏，progress 收尾统一同步。

## 假设塌方就停

撞见下列任一，停止写码、退回 plan / spec：
- 需修改已确认的接口才能继续
- 出现方案没覆盖的边界
- 同一处反复打补丁
- 实现与 spec 描述的不是一回事

## 快道

plan 判快道后直接进 cycle（不经过 progress，因为状态没变）。cycle 跑完后在 spec §7 快道调整日志里加一条：
```
调整内容 · 实现（改在哪）· 测试验收（怎么证明好了）· 判定依据（对照哪条 Mx.y 验收标准、结论为何）
```

三条规矩：验收栏不许空、判定依据栏不许空、只收快道条目。

## 边界

- **无状态**——cycle 不存任何上下文，全靠 PROGRESS.md
- **不自发 git**——只读查看（status / diff / log）不受限
- 不做档位判定（→ acr-plan）
- 不做 F2/F3 对账（→ acr-progress）
- 不做设计评审（→ plan 之后的审点）
- 不写 prd/spec（→ acr-brainstorm / acr-spec）
