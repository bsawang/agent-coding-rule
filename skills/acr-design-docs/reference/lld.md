# 详细设计模板

落点：`docs/specs/<domain>/<slug>.lld.md`

回答的是「**怎么写**」。目标：照着它能写码，不用再回来问。

## 结构

```
1 范围          对应概要设计的哪个模块 / 哪几条 F
                章节目录顺序 = 概要设计的模块顺序
2 接口          签名 / 入参出参 / 错误码 / 幂等性
3 数据结构      字段 + 约束 + 索引
4 流程与算法    主流程 + 分支 + 状态机
5 错误与边界    异常路径 / 并发 / 超时 / 空值 / 越界
6 测试要点      对应哪些测试用例 / 哪条验收标准
```

## 写作要点

**第 2 节 接口** —— 写全「调用方必须知道的一切」：类型签名、不变量、调用顺序约束、错误模式、需要的配置、性能特征。只写签名不够 —— 调用方还栽在不变量和调用顺序上。

**第 5 节 错误与边界** —— 这一节最容易糊弄，也最容易出事。错误路径要和正常路径**一样详细**：每种错误怎么发生、返回什么、调用方该怎么处理。并发、超时、空值、越界各自要有明确结论，哪怕结论是「不处理，因为 X」。

**第 6 节 测试要点** —— 每条都要能对到一条验收标准。对不上，说明要么功能点漏了，要么测试跑偏了。

**代码片段**：只在不写就说不清的地方用（状态机、reducer、schema、类型形状），裁剪到只留承载决策的部分，不要放整段实现。

## 合格线（写完逐条过）

- [ ] 照着它能写码、不用再回来问吗？
- [ ] 错误路径和正常路径一样详细吗？
- [ ] 每个接口都写清不变量、调用顺序和错误模式了吗？
- [ ] 每条测试要点能对到一条验收标准吗？
- [ ] 有没有「等等」「TBD」这类无主表述？
- [ ] 章节目录顺序 = 概要设计的模块顺序吗？
