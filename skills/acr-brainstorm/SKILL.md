# 头脑风暴 + prd 收敛

**输入**：一个要解决的问题或需求 —— 哪怕只有一句话。
**输出**：prd.md（业务层：项目定位 + 模块 Mx + 功能描述 + 非目标 + 状态后缀）。

没有这一步，方案的窟窿会在写码时才暴露，那时返工代价最高。

## 阶段一：发散

1. **澄清目标** —— 问清三件：要解决什么问题？成功长什么样？什么算失败？
2. **盘约束** —— 技术栈、存量资产、不能动的东西、时间、依赖方。
3. **铺路径** —— 至少 3 条可行路径，另加至少 1 条「荒谬」路径。荒谬的那条用来防锚定：它常常暴露被默认接受的前提。
4. **换视角各想一轮** —— 使用者 / 运维 / 半年后的自己 / 「必须做到 10 倍会怎样」。
5. **标假设** —— 每条路径写下它成立所依赖的假设。

**完成判据**：每条路径都能说出「它在赌什么」。

## 阶段二：收敛成 prd.md

把发散结论组织成 prd.md，这是**设计层的正式产出**，后续 spec / plan / progress 都引用它。

### prd.md 结构

```markdown
# {项目名} 业务需求 (prd)

## 0. 元信息
  状态（active / planned / deprecated） / 日期 / 决策人

## 1. 项目定位
  这是什么 · 核心价值 · 解决什么问题

## 2. 模块与功能描述

  ### M1 {模块名} 🟢⏳⬜
    用户能做什么 · 对用户的价值 · 一句话描述
    （模块级状态后缀，与 PROGRESS.md 镜像）

  ### M2 {模块名}
    ...

## 3. 非目标
  明确不做什么。必须写，防范围蔓延。

## 4. 调整记录（新增/废弃/改范围）
  | 日期 | 调整 | 原因 |
```

### 收敛规则

- 模块 Mx 的切分粒度：一个模块 = 一个**业务价值单元**（用户视角能单独感知的功能域）
- Mx 编号首次分配后**永不重排**，废弃标题加 🗑 —— 完整编号规范见 [acr-spec/reference/numbering.md](../acr-spec/reference/numbering.md)
- 增量修订时，只改 Mx 的功能描述，不动已有 Mx 的编号
- **状态后缀生命周期**：prd 写完时所有 Mx = ⬜（未开始）。🟢⏳ 是 progress 在 cycle 执行中**回写的镜像标记**——prd 自己不许改状态后缀。单一真相源在 `docs/PROGRESS.md`，由 progress skill 独占写权限。全局真相源体系（六层六源 + 禁止事项）见仓库根 `SSOT.md`。

### prd 边界（不许越界）

prd 是**业务层文档**，写「用户能感知到什么」。以下内容**一律归 spec**，prd 写了就算越界：

| prd 不许写 | 举例 |
|---|---|
| DB schema / 表结构 / 索引 | `CREATE TABLE todos (...)` |
| 接口签名 / 函数签名 | `add(title: str, priority: int) -> int` |
| 文件路径 / 目录结构 | `data/todos.db` |
| CLI 参数 / 命令行 flags | `--priority 1 --tag urgent` |
| 技术选型 | 用 SQLite / 用 click |
| 数据结构 / 字段约束 | `priority 1-5` |
| 协议 / 错误码 / 并发模型 | `exit 1 / exit 2` |

prd 只写：**功能描述（用户视角一句话）+ 非目标 + 模块切分**。技术实现细节由 spec 承接。

**完成判据**：prd.md 写完后交用户审（路径 A/B 的审点一）。审过了才能进 spec。

## rebuild 变体（有代码无文档）

输入是代码现状不是需求。先跑 acr-plan（rebuild 模式）拿事实快照：
1. 扫描代码结构 → 提取模块 / 函数 / 数据结构
2. 基于事实快照反推 prd.md 的模块划分和功能描述
3. prd 写完后交 spec 写详细设计

## 重构变体

重构的输入是现状而不是需求，两个产物替代上面的候选路径：

1. **行为基准** —— 先跑测试；没有测试就先补测试，把现有行为锁住。**没有基准不许动手。**
2. **变换清单** —— 一次一个可验证的小变换，按依赖序排列。

## 出口

- 新功能 / 增量 / rebuild → prd.md → 审 → acr-spec → acr-plan
- 重构变体 → 行为基准 + 变换清单 → 直接进 acr-spec

## 边界

- 不写技术规格（→ acr-spec，prd 审过之后）
- 不写实现代码（→ acr-cycle，plan + progress 之后）
- 方案已经存在、只需要拷问时，只用阶段二收敛 —— 不必重跑发散
