# 实施层进度

**落点**：`docs/PROGRESS.md`，**全项目一份**。

**定位**：实施层**唯一真相源**。prd/spec 里的 🟢⬜ 是本文件状态的**镜像标记**，只有本 skill 能改 PROGRESS.md，也只有本 skill 能回写 prd/spec 的状态后缀。全局真相源体系（六层六源 + 禁止事项）见 `docs/SSOT.md`。

**plan 做档位判定 + 事实预检查，progress 做计划侧对账。不重复。**

## 结构（硬约束，不许偏离）

**整体排序：全览（最前，索引，高频访问）→ 批次 1 → 批次 2 → ...（线性追加，永不重排）**

**核心设计：批次块只追加不搬运。归档时只改一个状态后缀 `⏳` → `✅`。**

**SSOT 分工：全览表状态列是唯一真相源；批次块子块是唯一证据存放地。**

### 关键约束

| 约束 | 说明 |
|---|---|
| **全览是状态唯一真相源** | 批次状态（✅⏳⬜）和子需求状态（全览"子需求"列里的 Mx.y✅⏳⬜）由 progress 独占写入 |
| **全览表是批次级索引** | 每行一个批次。子需求概要压缩在"子需求"列（`M1.1创建✅ M1.2查询✅`） |
| **批次块 = 标题 + 元信息行 + N 个 Mx.y 子块** | 每个子块自包含：标题（Mx.y + 概要 + 状态emoji）+ RED/GREEN/回写/待定 紧凑列表。子块按依赖序排列 |
| **全览表 4 列** | 批次 / 状态 / 子需求（概要+状态压缩） / 备注（覆盖+归档状态合并） |
| **子块标题 = Mx.y + spec §4 子需求标题** | progress 创建 PROGRESS 时从 spec 一次性提取（`#### M1.1 创建待办` → 抄"创建待办"），cycle 不改 |
| **批次块永不重排** | 归档只改标题状态后缀（`⏳` → `✅`），新批次直接 append 到末尾 |
| **批次号暗示顺序** | 批次 N+1 一定在批次 N 之后 |
| **⏳ 只在两处** | 全览批次状态列 + 全览子需求列里的 Mx.y + 当前进行中批次块的子块标题。已归档批次不许有 ⏳ |
| **GREEN 必须带输出片段** | 不许只写"passed"，必须加关键输出（`6 passed in 0.03s`）。F1 对账核心是"输出在本轮对话里" |
| **cycle 要么 ✅ 要么塌方** | 中间断 = 塌方，写"回写"行。不搞"内部步骤游标" |
| **依赖序只在元信息行说一遍** | 子块自然按依赖序排列即可，无需额外标注 |

## 硬规矩

- **plan 交出下发声明后必须过计划侧对账**才能交给 cycle（对账清单见 [reference/quality-checklist.md](reference/quality-checklist.md) §4）——只查 spec 三步不覆盖的项：
  - 依赖图拓扑序无环
  - 每个本批次内的待定项有主有期
  - PROGRESS.md 结构正确（全览是批次索引 + 批次块 = 一个表格 + 永不重排）
  - spec 的 MX 集合 / 验收完整性已经由 spec 三步对账保证，progress 不重复查
- **cycle 写 ✅ 必须有证据**（F1 内置）：验收命令的原始输出必须在**本轮对话内**
- **F2/F3 是 progress 收尾时的硬门槛**，cycle 不自己做
- **需求回写栏是 cycle 执行中唯一能改 prd/spec 计划的地方**——cycle 不直接改 prd/spec，先写回写栏，progress 收尾统一同步
- **同步顺序不能反**：先落回 prd/spec → 再追加调整记录（prd §4 + spec 调整记录） → 再清空回写栏 → 最后标 progress 归档
- **调整记录永不删除**——追加不覆盖。废弃条目物理隔离到 prd/spec 末尾「已废弃」章节（模板见 numbering.md §1）

## 边界

- 不做档位判定 / 事实预检查 / 影响评估（→ acr-plan）
- 不写 prd/spec（→ acr-brainstorm / acr-spec）
- 不执行代码（→ acr-cycle）
