# 实施层进度

**落点**：`docs/PROGRESS.md`，**全项目一份**。

**定位**：实施层**唯一真相源**。prd/spec 里的 🟢⬜ 是本文件状态的**镜像标记**，只有本 skill 能改 PROGRESS.md，也只有本 skill 能回写 prd/spec 的状态后缀。全局真相源体系（六层六源 + 禁止事项）见 `docs/SSOT.md`。

## 生命周期

```
plan 交出下发声明 → progress 接收 + 计划侧对账 → 过 → progress 写 PROGRESS.md（全览 + 批次 1 块）→ 交给 cycle

cycle 执行中：cycle 写证据 / 写需求回写 → 实时更新批次块

批次内所有子需求收点 → progress 收尾（F2+F3 清单见 [reference/quality-checklist.md](reference/quality-checklist.md) §6）：
  ① F2 三方 diff（spec 验收 ↔ progress 证据 ↔ 代码测试）
  ② F3 代码↔设计（大漂移拦、小漂移记）
  ③ 归档：改批次块状态后缀 ⏳ → ✅；全览状态列更新；同步 prd/spec
  ④ 追加新批次块（如果还有工作）
  完成

全项目完成 → 所有全览 Mx.y = ✅ → prd/spec 全 🟢
```

**plan 做档位判定 + 事实预检查，progress 做计划侧对账。不重复。**

## 结构（硬约束，不许偏离）

**整体排序：全览（最前，索引，高频访问）→ 批次 1 → 批次 2 → ...（线性追加，永不重排）**

**核心设计：批次块只追加不搬运。归档时只改一个状态后缀 `⏳` → `✅`。**

**SSOT 分工：全览表状态列是唯一真相源；批次块证据列是唯一证据存放地。**

```markdown
# {项目名} 开发进度

## 全览（索引 —— 唯一真相源）
| Mx.y | 状态 | 批次 |
|---|---|---|
| M1.1 | ✅ | 批次 1 |
| M1.2 | ✅ | 批次 1 |
| M2.1 | ⏳ | 批次 2 |
| M2.2 | ⬜ | — |

## 批次 1 ✅ {覆盖：prd §M1 / spec §M1.1-M1.3}  ✅ 已归档
  ① 批次号 + 覆盖范围（引用 prd/spec 编号）
  ② 依赖序（M1.1 → M1.2 → M1.3）

  | 子需求 | 状态 | 证据 |
  |---|---|---|
  | M1.1 | ✅ | ❌RED: ImportError...(2026-09-17 本轮) / 6 passed |
  | M1.2 | ✅ | 5 passed（2026-09-17 本轮） |
  | M1.3 | ✅ | 3 passed（2026-09-17 本轮）|

  ③ 子需求表（只列 Mx.y；cycle 要么 ✅ 要么塌方，没有中间状态）

  ④ 需求回写（cycle 执行中发现偏差时追加，progress 收尾落回后清空）
  ⑤ 待定（本批次内必须解决的阻塞，progress 收尾清空）

## 批次 2 ⏳ {覆盖：prd §M2 / spec §M2.1-M2.2}  ⏳ 进行中
  ①②④⑤ 同上
  ③ 子需求表同上
```

### 关键约束

| 约束 | 说明 |
|---|---|
| **全览是唯一真相源** | 状态列由 progress 独占写入。批次块状态列是镜像（归档时同步改） |
| **全览表按 Mx.y 编号序** | 新增 Mx.y 追加到底行，永不重排 |
| **批次块永不重排** | 归档只改状态后缀（⏳ → ✅），新批次直接 append 到末尾 |
| **批次号暗示顺序** | 批次 N+1 一定在批次 N 之后。全览"批次"列指向证据位置 |
| **批次块 6 要素** | 覆盖 / 依赖序 / 子需求表 / 需求回写 / 待定 / 状态后缀 |
| **子需求表按编号自然序** | 按 M1.1, M1.2, M1.3... 排。依赖序已在批次块 ② 字段单独列出 |
| **⏳ 只在两处** | 全览状态列（唯一游标）+ 当前进行中批次块后缀。已归档批次块（✅）不许有 ⏳ |
| **证据列 = 命令 + 输出片段** | 不许只写命令名，必须加关键输出（`4 passed in 0.03s`）。F1 对账核心是"输出在本轮对话里" |
| **cycle 要么 ✅ 要么塌方** | 中间断 = 塌方，写需求回写栏。不搞"内部步骤游标" |

## 硬规矩

- **plan 交出下发声明后必须过计划侧对账**才能交给 cycle（对账清单见 [reference/quality-checklist.md](reference/quality-checklist.md) §4）——只查 spec 三步不覆盖的项：
  - 依赖图拓扑序无环
  - 每个本批次内的待定项有主有期
  - PROGRESS.md 结构正确（按批次分块 + 6 要素 + 无模块级行）
  - spec 的 MX 集合 / 验收完整性已经由 spec 三步对账保证，progress 不重复查
- **cycle 写 ✅ 必须有证据**（F1 内置）：验收命令的原始输出必须在**本轮对话内**
- **F2/F3 是 progress 收尾时的硬门槛**，cycle 不自己做
- **需求回写栏是 cycle 执行中唯一能改 prd/spec 计划的地方**——cycle 不直接改 prd/spec，先写回写栏，progress 收尾统一同步
- **同步顺序不能反**：先落回 prd/spec → 再追加调整记录（prd §4 + spec 调整记录） → 再清空回写栏 → 最后标 progress 归档
- **调整记录永不删除**——追加不覆盖。废弃条目物理隔离到 prd/spec 末尾「已废弃」章节（模板见 numbering.md §1）

## 边界

- 不做档位判定 / 事实预检查 / 影响评估（→ acr-plan）
- 不写 prd/spec（→ acr-brainstorm / acr-spec）
- 不执行代码（→ acr-cycle）
