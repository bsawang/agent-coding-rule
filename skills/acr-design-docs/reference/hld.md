# 概要设计模板

落点：`docs/specs/<domain>/<slug>.hld.md`

回答的是「**分几块**」，不是「怎么实现」。技术选型一律下沉到架构设计。

## 结构

```
1 设计目标与范围  要建/改哪些能力，对应 spec 的哪几条 F 编号
2 模块划分        模块清单，按依赖序排列（被依赖者在前）
3 主要流程        关键路径的时序（文字或 ASCII）
4 数据概览        主要实体 + 关系（不展开字段）
5 接口概览        对外接口清单（签名级，不展开）
6 影响面          改动了哪些既有模块 / 数据
```

## 写作要点

**第 2 节 模块划分** —— 每个模块四件事：职责（一句话）、输入、输出、依赖谁。被谁依赖由下游模块的「依赖谁」反向体现，不必重复列。

```
订单模块
  职责   接收下单请求，落库并发出 OrderPlaced 事件
  输入   下单请求（用户、商品、数量）
  输出   OrderPlaced 事件 + 订单号
  依赖   库存模块（扣减）、支付模块（授权）
```

**按依赖序排列**：库存和支付排在订单前面，因为订单依赖它们。读者从上往下读一遍就能建立完整模型。

**第 3 节 主要流程** —— 只画关键路径，不画全部。异常分支在第 6 节或详细设计里。

## 合格线（写完逐条过）

- [ ] 改任一模块，能一句话答出「谁会受影响」吗？
- [ ] 模块依赖有没有环？
- [ ] 每个模块的职责能不能一句话说清 —— 说不清就是模块切错了？
- [ ] 模块顺序是依赖序吗（被依赖者在前）？
- [ ] 第 1 节的每条目标都能对到 spec 的某个 F 编号吗？
- [ ] 有没有混进技术选型或字段级细节（那属于架构设计 / 详细设计）？
